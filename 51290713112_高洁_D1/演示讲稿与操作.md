## 1:30—2:30 关键源码

打开 `code/src/train.py`，展示 `DistributedSampler`、DDP 包装、微批循环及 `loss / accum_steps`。说明普通同步每个微批反向都触发同步，延迟同步用 `no_sync()` 包围前 K−1 次前向和反向，在最后一次反向同步，再执行一次优化器更新。展示 `code/src/launch.py` 的双进程启动。

## 2:30—4:00 实际小规模演示

在项目目录 PowerShell 中运行下列命令；它们使用合成数据及新目录，不覆盖正式结果。等待训练时解释输出的 `update` 时间与 Loss；Gloo 初始化可能需要数秒。

```powershell
conda activate ddp-lab
$env:PYTHONUTF8='1'; $env:OMP_NUM_THREADS='1'; $env:MKL_NUM_THREADS='1'
$demo = 'results/demo_' + (Get-Date -Format 'yyyyMMdd_HHmmss')
python code/src/check_sampler.py
python code/src/launch.py --fake-data --batch 4 --accum-steps 2 --strategy delayed --warmup 0 --steps 1 --output $demo --experiment-id demo
```

## 4:00—4:50 数值正确性

展示 `code/src/verify.py` 和 `results/manual_20261125_223126/terminal_user.txt` 中实际验证结果：K=1、2、4、8 均通过，各 Rank 参数误差为 0，单进程参考的最大参数误差为 1.1920929e-07。程序比较固定输入下普通与延迟同步的梯度、更新参数、Rank 参数及单进程参考；该测试不证明长期训练轨迹完全一致。

## 4:50—6:20 A/B/C 结果

展示报告中的两批对照表和 `figures/comparison/throughput_k.png`。两批 A1 吞吐量分别为 191.72、198.20 样本/秒，A2 为 156.22、181.36；本机双进程没有加速。K=4 延迟同步分别为普通同步的约 2.33、2.40 倍。说明 B 组固定有效批大小和 K，C 组 K 与有效批大小同时变化，不能把跨 K 的差异全部归因于同步。

## 6:20—7:20 通信采样

展示 `code/src/profiler.py` 和 `figures/comparison/events.png`。K=1、2、4、8 时两批独立采样的普通同步 Gloo 事件数为 1、4、10、22，延迟同步均为 1。同步轮数不等于 All-Reduce 事件数，后者受梯度桶划分与重建影响。Profiler 使用合成输入，累计事件耗时不是端到端通信开销。

## 7:20—8:40 结论与限制

“本机短时测试中，双进程通信和调度开销可能抵消并行收益；在相同 K 和批大小下，延迟同步减少同步频率并提高吞吐量。实验每组只测量 4 次更新、重复 3 轮且采用同一随机种子，未实测 CPU 利用率或内存峰值，CPU/Gloo 结论不能直接推广到 GPU/NCCL 或长期收敛。”展示 `results/final/`、`results/manual_20261125_223126/` 与报告，结束录制。
