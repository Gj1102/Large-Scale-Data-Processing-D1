# 演示讲稿与录制指南

建议 8–9 分钟，严格小于 10 分钟，全程显示本人摄像头。本人仍需录制视频并如实填写个人信息。

## 0:00–0:50 题目
大家好，本实验研究数据并行与梯度同步开销。必做部分比较单进程和双进程，选做方向比较梯度累积与 no_sync 延迟同步，并检查梯度、参数和训练流程的正确性。

## 0:50–2:20 原理
DDP 每个进程持有模型副本并处理分片数据，反向传播时按桶执行 All-Reduce 并平均梯度。有效全局批大小是进程数乘微批大小乘累积步数。每次微批的 loss 除以 K，累积完成后只更新一次。普通同步每次反向传播都同步；no_sync 覆盖前 K−1 次的前向和反向，最后一次同步。梯度桶的重建会影响 All-Reduce 事件数。

## 2:20–3:30 环境与实现
展示 results/environment.json、src/launch.py 与 src/train.py。本机 Windows CPU 使用两个独立 Gloo 进程和 file:// 初始化，Linux CUDA 路径保留但未在本机测试。介绍 DistributedSampler、loss 缩放、no_sync 和一次 optimizer.step。完整更新耗时在每个 rank 上计时并取最大值，样本吞吐量用总样本除以总更新耗时。

## 3:30–4:35 正确性
展示 results/repeated/verification.log 或运行 `python src/verify.py`。两种同步策略的梯度最大差 1.19e-7，参数更新差 1.49e-8，两个 Rank 参数差为零。相同样本的单进程参考与 DDP 更新差 1.19e-7。训练两步后的测试集准确率为 11.38%，仅验证评估流程，不代表收敛结果。

## 4:35–6:45 结果
展示提交目录 figures/repeated 的图。每组预热两次、测量 512 个样本、重复三次；这是受 CPU 时间限制的缩减测量。单进程 A1 平均 203.3 样本每秒，双进程 A2 为 174.0，样本顺序没有逐样本对齐。B1 三轮为 55.4、56.7、54.6，B2 为 132.2、134.9、140.5，平均分别为 55.6 与 135.9。每轮仅有四个测量更新，方向一致但不能断言长期稳定。K 图中每组测量样本相同，但 K 改变有效批和更新次数，不把性能对照误称为收敛对照。展示 profiler 图：合成输入下 K=4 普通同步 10 个 Gloo 事件，延迟同步 1 个。桶重建、计算重叠和 profiler 开销使累计事件耗时不能当作端到端额外通信成本。

## 6:45–8:15 总结与限制
本次 CPU 结果中，双进程未加速；延迟同步降低观测到的同步事件，B2 在三轮中均有更高吞吐。短实验、采样顺序、CPU 调度等限制适用范围；微批独立耗时、计算通信重叠和 GPU/NCCL 未测。Codex 参与代码、实验、分析与报告整理，本人应如实说明自己的核验与独立工作。
